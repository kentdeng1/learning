## 1. 位域结构体

**一句话**:用 struct 语法把整字按 bit 拆成成员,编译器负责打包。

```c
struct REG {
    uint32_t en   : 1;   /* bit0   */
    uint32_t mode : 2;   /* bit1~2 */
    uint32_t div  : 4;   /* bit3~6 */
    uint32_t      : 1;   /* 匿名位域 = 填充,跳过 bit7 */
    uint32_t irq  : 8;
    uint32_t rsv  : 16;
};
```

| 规则       | 内容                                                   |
| -------- | ---------------------------------------------------- |
| 位序       | 先声明占低位(GCC/ARM 小端)——**实现相关,非标准保证**                   |
| 基类型      | 标准仅 `_Bool/int/unsigned`;GCC/Keil 支持 `uint8/16/32_t` |
| 无地址      | `&reg.en` 非法、不能进数组、不能 scanf                          |
| 零宽 `:0`  | 强制下一个成员换新的存储单元                                       |
| signed 坑 | `int x:1` 读出来是 -1;一律用 unsigned                       |

**定位**:位域是给**内存里的数据结构**(省 RAM、协议字段可读)用的语法糖,**不是给硬件寄存器**用的。厂商库(CMSIS/HAL)映射外设寄存器时全部用 `#define Msk` 掩码,理由:位序不可移植 + RMW 隐患 + volatile 读可能被合并。

## 2. 寄存器位类型(读 datasheet 必备)

**核心心法:写入"W1C/W0C"位不是存值,是触发副作用;状态只能读,永远写不出。**

| 缩写        | 语义            | 典型用途          |
| --------- | ------------- | ------------- |
| rw        | 普通读写          | 配置位           |
| r / ro    | 只读            | 状态位           |
| wo        | 只写(读回 0)      | 触发寄存器         |
| **W1C**   | 写 1 清除,写 0 忽略 | 中断 pending 标志 |
| **W0C**   | 写 0 清除,写 1 忽略 | 低有效事件/状态位     |
| W1S / W0S | 写 1/0 置位      | set 类寄存器      |
| RC        | 读一次自动清 0      | 事件状态(读即消费)    |
| T         | 写 1 翻转        | LED/引脚控制      |

**为什么设计成 W1C**:让"清标志"变成单向写,不用"先读再写",从根上消灭 RMW 竞争窗口。

**set/clear 别名寄存器 = W1 系思想**:如 `GPIO->BSRR` 低 16 位写 1 置位、高 16 位写 1 清位,写 0 忽略 → 单条写即安全,永远不需要读改写。

## 3. RMW(读-改-写)与驱动红线

**原理**:对普通 rw 位,"改其中一位"编译成 LDR → ORR/BIC → STR 三步,不原子。窗口内硬件/ISR 改过寄存器,回写即覆盖。

| 想做什么   | 位类型    | 正确写法              | 禁止写法                        |
| ------ | ------ | ----------------- | --------------------------- |
| 清中断标志  | W1C    | `REG = (1<<n);`   | `REG \|= (1<<n)`、`bf.f = 0` |
| 清低有效事件 | W0C    | `REG = ~(1<<n);`  | `\|\=` / `&=`               |
| 置位     | rw/W1S | `REG \|= (1<<n);` | —                           |
| 有别名寄存器 | —      | `BSRR = (1<<n);`  | `REG \|= (1<<n)`            |

**红线**:碰到 C(清除)语义的位,永远不要用 `|=` / `&=` 去改——整字直写,只让目标位是触发值。W1C 用 `|=` 会把快照里其他 pending 标志一起写 1 误清(丢中断)。

## 4. 宏:双重求值陷阱

**一句话**:宏是预处理期文本替换,参数出现 N 次就求值 N 次——没有"先算一次存起来"的语义。

```c
MAX(x++, y++)
≡ ((x++)>(y++) ? (x++) : (y++))
/* 比较各 ++ 一次;胜者分支再 ++ 一次 → 胜者 ++2 次 */
/* x=5,y=8 实测:m=9, x=6, y=10(y 只该到 9) */
```

**解法三档**:

1. GCC 语句表达式 + typeof(AC6/armclang 可用,AC5/C51 不行):
   ```c
   #define MAX(a,b) ({ \
       __typeof__(a) _a = (a); \
       __typeof__(b) _b = (b); \
       _a > _b ? _a : _b; })
   ```
2. static inline(标准 C,类型写死):
   ```c
   static inline int imax(int a, int b) { return a > b ? a : b; }
   ```
3. 治标:约定宏实参不带副作用(老代码库现实解)。

**隐藏坑**:无副作用也可能出事——`MAX(slow_func(), 0)` 会把 slow_func 调两次。"调用"本身就是副作用。

## 5. static inline = 宏的正确替代品

**拆词**:`inline`(建议编译器在调用点展开,省调用开销;听不听都行,语义不变)+ `static`(本 .c 私有,放头文件多文件包含不冲突)→ **能安全放头文件、零调用开销、参数语义正确的真函数**。

**为什么安全**:实参在调用点求值一次 → 按值拷进形参 → 函数体用的是副本,用几次都不碰实参。宏没有这道拷贝边界。

| 维度    | 宏              | static inline  |
| ----- | -------------- | -------------- |
| 参数求值  | 出现 N 次求 N 次    | 调用点恰一次         |
| 类型检查  | 无              | 有              |
| 头文件复用 | 天然             | 加 static 才可    |
| 类型泛型  | typeof(GCC 扩展) | 写死 / \_Generic |
| 调试    | 全糊在调用点         | 可单独断点          |

**嵌入式事实**:CMSIS/HAL 的 `__STATIC_INLINE`(展开即 static inline)大量用于寄存器操作——封装可读性 + 内联零开销,这正是宏当年垄断位操作的领域。
