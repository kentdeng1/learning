## C 函数指针讲解(补 C 核心机制)

K 自问自答式提问:"函数指针 = 传函数入口地址?工程上用在接口分层解耦?"——理解方向对,做了精度补全。

讲解要点:
- 精度补全:函数名在表达式中退化为入口地址,`f` / `&f` / `*f` 等价,`fp()` 与 `(*fp)()` 等价
- 两种工程模式必须区分:
  - **回调 callback** = 控制反转(IoC),上层把函数交给下层,下层决定何时调用
  - **ops 接口表 / vtable** = C 的多态,上层持有函数指针表,运行时选实现
- 加分细节:HAL 传统 `HAL_UART_RxCpltCallback` 是 `__weak` 覆盖机制,**不是**函数指针;新版 `HAL_UART_RegisterCallback()` 才是
- 坑:NULL 调用 = HardFault、间接调用无法内联(ISR/高频路径慎用)、const 表放 Flash、类型严格匹配

产出:
- demo `code/funcptr_demo.c`(gcc 编译运行已验证):地址等价、回调注册、ops 表切换 HW/SW I2C、命令跳转表
- 关联:可与 `notes/c-bitfield-macro-cheatsheet.md` 合并为 C 核心机制速查

观察:K 提问方式从"这是什么"转向"我的理解对不对 + 工程怎么用",自主归纳能力在提升,继续保持"先确认理解 → 补精度 → 给工程图谱"的讲解节奏。

### 追加:回调的"谁来注册"卡点 + 多订阅版本

K 追问"注册是谁去注册的" —— 这是回调模式最容易卡住的点。已用 t0/t1 两时刻时序图澄清:
- 注册 = 上层在 main/init 主动调用下层的 register_xxx(),只存地址不调用
- 回调 = 之后事件触发时下层按存下的地址跳过去,下层不知道那是谁
- 对比"不用回调就得 extern 上层函数名"说明解耦价值

应 K 要求补多订阅(发布-订阅)版本:
- 单指针 → `g_subs[]` 静态数组;subscribe 去重 + 找空位;unsubscribe 置 NULL;notify 遍历跳过 NULL
- demo `code/callback_multicast_demo.c`(gcc -Wall -Wextra 零警告,已验证):无订阅→丢弃、三模块同时收到、重复订阅不重复、注销、容量满拒绝
- 工程要点:静态数组而非 malloc、注销比注册更重要(防野指针)、notify 在 ISR 里需临界区且别拉长 ISR(推荐 ISR 置标志/推队列,主循环 notify)、RTOS 下更推荐事件组/队列替代
