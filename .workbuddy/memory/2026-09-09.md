## K 的代码审查:函数指针类型不匹配(能跑但错)

K 贴代码问"我这个写法有问题吗":
```c
typedef int (*g_cb_t)(unsigned int *data);   /* 期待指针 */
int add_p(unsigned int data){ return data+10; }  /* 实际是值 */
g_cb = add_p;  g_val = g_cb(5);   /* 打印 15, 看着对 */
```

诊断(本地 gcc -Wall -Wextra 复现):
- 两个警告:`-Wincompatible-pointer-types` + `-Wint-conversion`("makes pointer from integer")
- 输出确实 15 → **典型"能跑但错"的 UB**
- 能跑对的原因:ARM AAPCS / x86-64 下整数参数走同一寄存器,两边都当整数读,纯属巧合
- 炸的条件:函数里解引用(`*data + 10` → 访问地址 0x5 → HardFault);参数为 float/结构体(走不同寄存器/栈)立刻错

教学点:
- 函数指针类型必须**逐项匹配**(返回值 + 每个参数类型/顺序/个数);`unsigned int` ≠ `unsigned int *`
- 自查法:把 typedef 名字删掉看签名 `int (unsigned int *)` vs `int (unsigned int)`
- **禁止用强转 `(g_cb_t)add_p` 消警告** — 只是埋炸弹
- `-Wincompatible-pointer-types` 在嵌入式里要当错误处理
- 附带:`printf` 用 `%u` 打 unsigned int;`g_cb = NULL` 初始化是好习惯,调用前判空

产出 demo `code/funcptr_typematch_demo.c`(零警告):值参数版 A + 指针参数版 B + 危险说明。

观察:K 开始主动贴自己的代码求审,这是从"学"到"写"的转折信号。后续应多鼓励他贴代码,并对他的代码做逐行审查式反馈(比纯讲概念对他更有效)。

## Makefile 系统教学

K 要求学写 Makefile。讲解:规则三要素(target/prerequisites/recipe)+ 时间戳决策(目标不存在 OR 依赖更新 → 执行,否则 up to date)+ 语法速查表(变量 :=/=、自动变量 $@ $< $^、模式规则 %、.PHONY、wildcard/patsubst、@ 与 -)。

产出练习项目 `code/mk-tutorial/`(main.c + calc.c + calc.h + 带中文教学注释的 Makefile),已用 mingw32-make 完整验证四种场景:

强调的两个坑:recipe 必须 Tab(missing separator)、头文件依赖必须靠 .d 自动生成否则"改了 .h 不生效"。

### K 的卡点:变量 vs 规则混淆

K 追问"OBJS 是不是命令/把 .c 编译成 .o?"、"DEPS 是不是把 .o 输出 .d?"、"exe 什么时候生成?"。

已在本地实证澄清:
- **变量只做字符串替换,不执行任何动作**;真正干活的是带 recipe 的规则
- `.d` 不是从 `.o` 生成 —— 是 gcc 编译 .c 时因 `-MMD -MP` 顺带写出的**文本依赖清单**(`main.o: main.c calc.h`),再由 `-include` 读回
- exe 由链接规则 `$(TARGET)$(EXE): $(OBJS)` 生成,在 [A] 输出的第三条命令;make 顺序:all → app.exe → 缺 .o → 先编译 .o → 再链接
- 教他用 `make -n`(看展开)和 `cat main.d`(看依赖清单)自行验证

K 打字漏 `$`(`(SRCS:.c=.o)`),已提醒必须是 `$(...)`。
提醒:测试文件名用英文/下划线,避免 Windows 终端编码问题(延续 GBK 教训)。

## extern 对函数 vs 变量(C 易混点)

K 问"为什么不用 extern 声明函数也能编译通过"。

答案:函数声明默认带 external linkage,`void foo(void);` ≡ `extern void foo(void);`;变量必须靠 extern 区分声明与定义(因为 `int g;` 无论有没有初值都是定义/tentative definition)。

三种"不用 extern 也能过":① 函数声明(默认 extern)② 定义写在调用前(定义即声明)③ **不声明直接调用 = 隐式声明**(C89 遗留,GCC 8.1 只警告,编译器假定返回 int → 返回 double/指针时 UB)。建议 `-Werror=implicit-function-declaration`。

实证 demo `code/extern-demo/`(a.c / b.c / b_bad_no_extern.c),已验证:
- 函数免 extern + 变量带 extern → 通过,输出 42
- 变量漏 extern + `-fno-common`(GCC 10+ 默认)→ multiple definition 报错
- 同样代码在 K 的 GCC 8.1(`-fcommon` 默认)→ **静默合并,bug 被隐藏**(换编译器才暴露)

规则:函数声明放 .h(extern 可省);全局变量 .h 必须 extern、仅一个 .c 定义;本文件私有一律 static。
